เริ่ม Lab

0 ทฤษฎี: GitHub CLI คืออะไร

GitHub CLI หรือ gh

เป็นเครื่องมือใช้งาน GitHub ผ่าน Terminal เช่น login, clone repo, สร้าง issue, ดู pull request, เปิด pull request และจัดการ repo โดยไม่ต้องสลับไปหน้าเว็บบ่อย ๆ

เหมาะกับใคร

นักศึกษา นักพัฒนา และทีมที่ต้องการทำงานร่วมกันบน GitHub แบบเร็วขึ้น โดยเฉพาะเมื่อต้องใช้คำสั่ง Git และ GitHub ในโปรเจกต์จริง

ภาพรวม Workflow

ติดตั้ง gh→Login GitHub→Clone / Repo→Branch→Commit + Push→Pull Request→Review + Merge

1 Lab 1: ติดตั้ง GitHub CLI

เป้าหมาย: ผู้เรียนติดตั้ง gh ได้ และตรวจสอบเวอร์ชันได้ด้วย gh --version

macOS: ตรวจชนิดเครื่องก่อน

uname -m
ผลลัพธ์ความหมายวิธีติดตั้งที่แนะนำ
arm64Apple Silicon เช่น M1/M2/M3/M4Homebrew หรือไฟล์ macOS_arm64.pkg
x86_64Mac Intelไฟล์ macOS_amd64.pkg

ทางเลือก A: ติดตั้งด้วยไฟล์ .pkg

  1. เข้าเว็บไซต์ https://cli.github.com/
  2. ดาวน์โหลดไฟล์สำหรับ macOS ให้ตรงกับเครื่อง
  3. ดับเบิลคลิกไฟล์ .pkg แล้วกด Continue → Install

ทางเลือก B: ติดตั้งด้วย Homebrew

brew install gh
ถ้าใช้ Mac Intel แล้ว Homebrew ไม่รองรับ ให้ใช้วิธีไฟล์ gh_*_macOS_amd64.pkg แทน

Windows

winget install --id GitHub.cli

หรือดาวน์โหลดจาก https://cli.github.com/ แล้วติดตั้งด้วยไฟล์ installer

Linux Ubuntu/Debian

sudo apt update
sudo apt install gh

หาก package repository ยังไม่มีเวอร์ชันล่าสุด ให้ติดตั้งตามคู่มือจาก GitHub CLI official site

ตรวจสอบหลังติดตั้ง

gh --version

2 Lab 2: Login GitHub ด้วย CLI

1

เริ่ม Login

gh auth login
2

เลือกตัวเลือก

What account do you want to log into?  GitHub.com
What is your preferred protocol?       HTTPS
Authenticate Git with credentials?     Yes
How would you like to authenticate?    Login with a web browser
3

ตรวจสอบบัญชี

gh auth status

ตรวจให้แน่ใจว่า login เป็นบัญชีที่มีสิทธิ์ push ใน repository

หลังจาก login สำเร็จ Git operation ผ่าน HTTPS จะใช้ credential ที่ GitHub CLI จัดการให้ ทำให้ push ได้ง่ายขึ้น

4 Lab 4: แชร์ GitHub Repository ให้ทีม

เป้าหมาย: ผู้เรียนสามารถแชร์ Repository ให้สมาชิกทีม และกำหนดสิทธิ์ที่เหมาะสมสำหรับการทำงานกลุ่ม

กรณี A: Repository อยู่ในบัญชีส่วนตัว

1. เปิด Repository
เข้า repo เช่น https://github.com/Tongjai-Yampaka/suki-system
2. เข้า Settings
คลิกเมนู Settings ของ repository
3. เพิ่ม Collaborator
เลือก Collaborators หรือ Collaborators and teams → Add people
4. ใส่ GitHub username
พิมพ์ username ของสมาชิก เช่น student-user01
5. สมาชิกต้องกดรับคำเชิญ
หากยังไม่กดรับ invitation จะยัง push ไม่ได้

กรณี B: Repository อยู่ใน Organization

สิ่งที่จัดการคำแนะนำ
Organizationสร้าง org สำหรับรายวิชา/ห้องเรียน เช่น CS-RMUTTO-GitLab
Teamแยกทีมตามกลุ่ม เช่น group-01, group-02
Permissionนักศึกษาใช้ Write, หัวหน้ากลุ่มใช้ Maintain, อาจารย์ใช้ Admin
Repositoryสร้าง repo แยกตามกลุ่ม เช่น suki-system-group-01

ระดับสิทธิ์ที่แนะนำ

Roleเหมาะกับคำอธิบาย
Readผู้สังเกตการณ์ดูและ clone ได้ แต่แก้ไขไม่ได้
Writeสมาชิกทีมทั่วไปpush branch, เปิด PR, แก้ issue ได้
Maintainหัวหน้าทีมจัดการบางส่วนของ repo ได้ แต่ไม่ถึงระดับเจ้าของ
Adminอาจารย์/เจ้าของโปรเจกต์จัดการ settings, collaborators และ delete repo ได้
สำหรับงานกลุ่มนักศึกษา แนะนำให้สมาชิกใช้ Write และให้อาจารย์/หัวหน้าทีมเป็นผู้ Merge Pull Request

5 Lab 5: Workflow ทำงานเป็นทีม

สถานการณ์ Lab

ทีมพัฒนา Suki System มีสมาชิก 3 คน ต้องแบ่งงานเป็นหน้าเมนู หน้าออเดอร์ และหน้าแดชบอร์ด โดยทุกคนต้องทำงานบน branch ของตนเอง แล้วเปิด Pull Request เพื่อรวมเข้า main

Member A

หน้าเมนู

feature/menu-page
Member B

หน้าออเดอร์

feature/order-page
Member C

Dashboard

feature/dashboard

คำสั่งสำหรับสมาชิกแต่ละคน

# 1) Clone repo
gh repo clone Tongjai-Yampaka/suki-system
cd suki-system

# 2) ดึง main ล่าสุด
git pull origin main

# 3) สร้าง branch ของตัวเอง
git switch -c feature/menu-page

# 4) แก้ไฟล์งาน แล้วบันทึก
git status
git add .
git commit -m "feat(menu): add menu page"

# 5) push branch
git push -u origin feature/menu-page

# 6) เปิด pull request
gh pr create --base main --head feature/menu-page --title "feat(menu): add menu page" --body "เพิ่มหน้าเมนูสำหรับระบบร้านสุกี้"

คำสั่งสำหรับหัวหน้าทีมหรือผู้ Review

gh pr list
gh pr view 1
gh pr checkout 1
# ทดสอบงานในเครื่อง
# ถ้าผ่าน ให้ merge
gh pr merge 1 --merge --delete-branch
หลักสำคัญ: ห้ามทำงานตรงบน main โดยไม่จำเป็น ให้สร้าง branch → push → PR → review → merge

! แก้ปัญหาที่พบบ่อย

403 ตอน Push

สาเหตุ: login ผิดบัญชี หรือไม่มีสิทธิ์ Write

gh auth status
gh auth logout
gh auth login

Remote URL ผิด

เช่นคัดลอก Markdown URL มาแทน URL จริง

git remote -v
git remote set-url origin https://github.com/Tongjai-Yampaka/suki-system.git

ยังไม่ได้รับ Invitation

ให้สมาชิกเข้า Notification หรือ Email แล้วกด Accept invitation

gh command not found

ติดตั้งไม่สำเร็จ หรือ PATH ยังไม่ถูกต้อง

which gh
gh --version
ข้อควรระวัง: อย่าแชร์ Personal Access Token หรือรหัสผ่านกับทีม ให้เพิ่มสิทธิ์ผ่าน Collaborator/Team แทน

✓ Checklist ส่งงาน Lab

? Quiz ตรวจคำตอบ

1) คำสั่งใดใช้ Login GitHub CLI
2) ถ้า push แล้วขึ้น 403 ควรตรวจอะไรเป็นอันดับแรก
3) วิธีทำงานทีมที่ปลอดภัยที่สุดคือข้อใด
4) Repository ส่วนตัวจะแชร์ให้เพื่อน push ได้ ต้องเพิ่มเป็นอะไร
